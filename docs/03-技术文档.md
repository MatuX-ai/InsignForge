## 二、整体架构

### 2.1 架构总览

InsightForge 个人版采用**微服务化模块架构**，所有组件均可通过 Docker Compose 一键编排启动。系统分为七个核心层次：

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           用户交互层                                        │
│                    React/Vue 单页应用 + TUI (Hermes)                       │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                           API 网关层                                        │
│                    Node.js + Express REST API                              │
│              (认证、路由、请求转发、配额管理)                                │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                        智能体编排层                                         │
│    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐              │
│    │   Hermes     │    │   Mastra     │    │DeepSeek      │              │
│    │   Agent      │◄──►│   Framework  │    │  Harness     │              │
│    │ (首席执行官)  │    │ (智能体运行时) │    │ (原型生成)   │              │
│    └──────────────┘    └──────────────┘    └──────────────┘              │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                         工作流引擎层                                        │
│              Workflow Automation MVP (免注册工作流引擎)                     │
│           (HTTP请求、代码执行、数据转换、Webhook)                           │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                         数据采集层                                          │
│    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐              │
│    │   Crawlee    │    │  OpenSerp    │    │  代理池      │              │
│    │ + Playwright │    │  (搜索引擎)   │    │  (可选)      │              │
│    └──────────────┘    └──────────────┘    └──────────────┘              │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                         数据持久化层                                        │
│              SQLite (开发) / PostgreSQL (生产)                             │
│         (需求库、项目数据、用户数据、执行记录)                               │
└─────────────────────────────────────────────────────────────────────────────┘
                                    │
                                    ▼
┌─────────────────────────────────────────────────────────────────────────────┐
│                         外部服务层                                          │
│    大模型 API (DeepSeek/OpenAI)  │  搜索引擎 API (OpenSerp/SerpAPI)        │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 2.2 架构原则

| 原则 | 说明 |
|------|------|
| **最少依赖** | 系统仅依赖 2 个外部 API（大模型 + 搜索引擎），其余全部自包含 |
| **免注册优先** | 所有核心组件无需向任何第三方平台注册账号 |
| **模块解耦** | 各模块通过清晰的 API 边界交互，可独立替换或升级 |
| **数据本地化** | 所有用户数据存储于本地数据库，不上传云端 |
| **配置驱动** | 通过环境变量和配置文件控制系统行为，无需修改代码 |


## 三、核心模块详解

### 3.1 Hermes Agent —— 首席执行官智能体

Hermes Agent 是 Nous Research 构建的**自进化 AI 智能体框架**，在 InsightForge 中担任“首席执行官 Agent”角色，负责整个调研流程的协调与决策。

#### 3.1.1 核心特性

| 特性 | 说明 |
|------|------|
| **内置学习闭环** | 从经验中创建技能（Skill），在使用中改进技能，主动持久化知识 |
| **跨会话记忆** | 通过 FTS5 搜索和 LLM 摘要实现跨会话记忆召回 |
| **三层记忆架构** | MemoryStore / MemoryManager / MemoryProvider 分层管理 |
| **模型无关** | 支持 200+ 种模型提供商，可通过 `hermes model` 命令随时切换 |
| **多平台部署** | 支持 $5 VPS、GPU 集群、Serverless 等多种基础设施 |
| **终端 TUI** | 完整终端界面，支持多行编辑、斜杠命令自动补全、对话历史 |
| **定时调度** | 内置 cron 调度器，支持无人值守的自动化任务 |
| **子代理委派** | 可生成隔离的子代理进行并行工作流处理 |

#### 3.1.2 架构组成

Hermes Agent 的内部架构包含以下主要子系统：

| 子系统 | 职责 |
|--------|------|
| **Agent Loop** | 智能体主循环，控制系统提示词组装和执行流程 |
| **Tool Registry** | 中央工具注册系统，声明式注册 + 集中式调度 |
| **Memory System** | 三层记忆架构（Store/Manager/Provider），冻结快照模型 |
| **Skills System** | 渐进式披露架构 + Curator 后台维护，支持技能归档和修剪 |
| **Provider Transport** | 统一抽象层，支持 Anthropic/Chat Completions/Responses API/Bedrock |
| **Browser Tool** | 多后端浏览器自动化，可访问性树 + 三层安全防御 |
| **Web Tools** | 8 种可插拔搜索/提取后端 |
| **Code Execution** | 代码执行沙箱，7 种工具限制 + 两种通信模式 |
| **Provider Plugin System** | v0.13.0 引入，支持 30+ 可插拔提供商 |

#### 3.1.3 在 InsightForge 中的角色

- **任务拆解**：将用户的“验证想法”请求拆解为数据采集、分析、报告生成等子任务
- **工具调度**：调用 Crawlee 爬虫、OpenSerp 搜索、大模型分析等工具
- **跨会话学习**：记住用户的偏好和历史决策，逐步优化调研策略
- **质量把控**：对生成的报告进行自我审查和迭代优化

### 3.2 Mastra —— 智能体运行时框架

Mastra 是一个用于构建 AI 智能体、工具和工作流的 **TypeScript 框架**。

#### 3.2.1 核心能力

| 能力 | 说明 |
|------|------|
| **Agent 类** | 提供创建 AI 智能体的基础，支持响应生成、流式交互和语音能力 |
| **工作流编排** | 支持结构化输出、控制流和错误处理策略 |
| **Studio UI** | 提供交互式 UI 用于 Mastra 项目的可视化调试 |
| **MCP 支持** | 支持 MCP 服务器规范，可集成系统级提示词 |

#### 3.2.2 在 InsightForge 中的角色

- **市场调研员智能体**：在 Mastra 中定义具体的智能体工作流
- **工具集成**：将爬虫、搜索、数据库等操作封装为 Mastra 工具
- **结构化输出**：确保智能体输出符合市场报告的数据结构

### 3.3 DeepSeek Harness —— 原型生成引擎

DeepSeek Harness (dsh) 是 DeepSeek AI 开发的**插件化智能体框架**。

#### 3.3.1 核心架构

DeepSeek Harness 基于 **Cordis** 框架构建，遵循 **“一切皆插件”** 的设计理念：

- **模型适配器**、**工具注册表**、**会话日志**、**智能体循环** 全部都是可替换的插件
- **不存在特权内核**：扩展 dsh 的方式是将插件挂载到其他插件旁边
- **Profile 与组合包**：通过 Profile 和 Bundle 机制实现灵活的配置组合

#### 3.3.2 核心包结构

| 包 | 职责 |
|----|------|
| `core/session` | 仅追加的 SessionEvent 日志和内存存储 |
| `core/system-prompt` | 系统提示词分节和工具模式组装 |
| `core/tools` | 作用域化的工具注册表和受控执行 |

#### 3.3.3 在 InsightForge 中的角色

- **代码模式**：利用 dsh 的代码模式生成验证落地页的 HTML
- **插件扩展**：可通过开发自定义插件扩展原型生成能力

### 3.4 Workflow Automation MVP —— 工作流引擎

Workflow Automation MVP 是一个**简化版的工作流自动化平台**，灵感来自 n8n。

#### 3.4.1 核心特性

| 特性 | 说明 |
|------|------|
| **无认证** | 开箱即用，无需注册或登录 |
| **可视化构建器** | 通过连接节点创建工作流 |
| **节点类型** | Manual Trigger、HTTP Request、Code、Set、Merge、Webhook |
| **实时日志** | 工作流执行时提供实时日志输出 |
| **REST API** | 完整的工作流管理 REST API |

#### 3.4.2 技术架构

| 组件 | 技术 |
|------|------|
| **HTTP 服务器** | Express.js |
| **存储** | 内存存储（MVP 阶段） |
| **节点系统** | 模块化、可扩展 |
| **执行引擎** | 基于数据流的工作流执行 |

#### 3.4.3 API 端点

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/workflows` | GET/POST | 列表/创建工作流 |
| `/api/workflows/:id` | GET/PUT/DELETE | 获取/更新/删除工作流 |
| `/api/workflows/:id/execute` | POST | 执行工作流 |
| `/api/executions` | GET | 列表执行记录 |
| `/api/executions/:id/logs` | GET | 获取执行日志 |
| `/webhook/:workflowId` | POST | 接收 Webhook 事件 |

#### 3.4.4 在 InsightForge 中的角色

- **数据采集调度**：定时触发 Crawlee 爬虫执行
- **智能体编排**：串联 Mastra 智能体的调用流程
- **数据流转**：在爬虫、数据库、智能体之间传递数据

### 3.5 Crawlee + Playwright —— 数据采集引擎

Crawlee 是 **JavaScript/TypeScript 网络爬虫框架**，提供端到端的爬取和抓取能力。

#### 3.5.1 核心组件

| 组件 | 说明 |
|------|------|
| **PlaywrightCrawler** | 基于 Playwright 的浏览器爬虫，支持 Chromium/Firefox/Webkit |
| **BrowserPool** | 智能管理浏览器的打开、关闭和页面生命周期 |
| **Router** | 基于请求标签的路由系统 |
| **AdaptivePlaywrightCrawler** | 自动在浏览器模式和 HTTP-only 模式间切换 |

#### 3.5.2 在 InsightForge 中的角色

- **论坛数据采集**：从 Reddit、Hacker News 等抓取讨论内容
- **社交媒体监控**：采集 Twitter、Product Hunt 等平台的公开数据
- **JS 渲染页面**：处理需要 JavaScript 执行的现代 Web 应用

### 3.6 OpenSerp —— 搜索引擎集成

OpenSerp 是**开源的搜索引擎结果 API**，支持 Google、Bing、百度、DuckDuckGo 等主流搜索引擎，可本地私有化部署。

#### 3.6.1 在 InsightForge 中的角色

- **市场热度分析**：通过搜索关键词获取结果数量，量化市场关注度
- **竞品识别**：搜索相关关键词，识别主要竞品
- **实时数据**：提供最新的网络公开信息

## 五、部署指南

### 5.1 系统要求

| 项目 | 最低配置 | 推荐配置 |

| **CPU** | 2 核心 | 4 核心 |

| **Python** | ≥ 3.11（Hermes Agent 依赖）| 3.11+ |

### 5.2 Docker Compose 部署（推荐）

#### 5.2.1 docker-compose.yml 示例

```yaml
version: '3.8'

services:
  # 后端 API
  backend:
    build: ./backend
    ports:
      - "3001:3001"
    environment:
      - NODE_ENV=production
      - DATABASE_URL=sqlite:/app/data/insightforge.db
      - LLM_PROVIDER=${LLM_PROVIDER}
      - DEEPSEEK_API_KEY=${DEEPSEEK_API_KEY}
      - OPENSERP_URL=http://openserp:8080
    volumes:
      - ./data:/app/data
    depends_on:
      - openserp
    restart: unless-stopped

  # 前端
  frontend:
    build: ./frontend
    ports:
      - "3000:3000"
    environment:
      - VITE_API_URL=http://localhost:3001
    restart: unless-stopped

  # OpenSerp 搜索引擎
  openserp:
    image: ghcr.io/openserp/openserp:latest
    ports:
      - "8080:8080"
    restart: unless-stopped

  # Workflow Automation MVP
  workflow:
    build: ./workflow
    ports:
      - "5678:5678"
    environment:
      - API_URL=http://backend:3001
    restart: unless-stopped

  # Hermes Agent (可选，可独立运行)
  hermes:
    image: nousresearch/hermes-agent:latest
    stdin_open: true
    tty: true
    volumes:
      - ./hermes-data:/root/.hermes
    restart: unless-stopped
```

## 八、故障排查

### 8.1 常见问题与解决方案

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| **服务无法启动** | 端口被占用 | 检查端口占用：`lsof -i :3000` |
| **API 调用失败** | API Key 无效或过期 | 检查 `.env` 中的 API Key 配置 |
| **爬虫无数据** | 目标网站反爬 | 配置代理池或降低请求频率 |
| **报告生成超时** | 大模型 API 响应慢 | 检查网络连接，考虑更换模型 |
| **Hermes 无法启动** | Python 依赖缺失 | 重新运行安装脚本 |
| **数据库锁定** | SQLite 并发写入冲突 | 迁移到 PostgreSQL |
