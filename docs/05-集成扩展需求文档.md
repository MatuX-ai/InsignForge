# InsightForge 个人版 —— 集成扩展需求文档

**版本**：v1.0
**最后更新**：2026年8月
**文档状态**：待评审


## 一、概述

### 1.1 文档目的

本文档定义将 InsightForge **核心市场调研能力** 抽取为独立 npm 包并以 **MCP（Model Context Protocol）服务器** 形态对外暴露的完整需求。目标是让任何支持 MCP 的 AI 客户端（Claude Desktop、Cursor、Cline、Continue 等）都能直接调用 InsightForge 的能力，同时通过 SDK 抽取解决 backend 与 dsh-plugin 双轨维护问题。

### 1.2 背景

当前 InsightForge 的核心算法存在**两处独立实现**：

| 位置 | 内容 |
|------|------|
| `backend/src/agents/MarketResearcher.ts` + `backend/src/services/*` | 后端 Express 服务内部实现 |
| `dsh-plugin/insightforge-dsh-plugin/src/core/researcher.ts` 等 | dsh 插件内部实现（438 行协调器） |

两份代码通过手工保持"字符级一致"，存在三类风险：
1. **同步漂移**：任何 prompt / schema 改动都可能遗漏一处
2. **能力碎片化**：每种集成形态（dsh 插件 / REST / CLI / 嵌入组件）都要重新实现一套核心
3. **MCP 缺位**：2026 年 MCP 已成为 AI 工具生态的事实标准，Claude Desktop、Cursor、Cline、Continue 等客户端均原生支持，但 InsightForge 尚未提供 MCP 接口

本次需求同时解决上述三个问题。

### 1.3 设计原则

| 原则 | 说明 |
|------|------|
| **单一权威实现** | 核心算法只存在于 `@insightforge/core` 一处，backend 和 dsh-plugin 都改为消费者 |
| **零外部依赖扩张** | SDK 不引入 HTTP/Express 等框架，保持纯算法库特性 |
| **MCP 协议原生** | MCP 服务器严格遵循 [MCP 规范](https://modelcontextprotocol.io)，可被任何合规客户端直接加载 |
| **配置驱动** | LLM / 搜索引擎 / 数据库 / 缓存 / 并发等所有可变参数均通过配置注入，禁止硬编码 |
| **向后兼容** | 抽取 SDK 不改变现有 backend API、dsh-plugin 工具接口；MCP 服务器可与 dsh-plugin 并存安装 |
| **可观测性** | 所有工具调用记录 session_id / duration / token 估算，便于后续调试 |

### 1.4 与现有架构的关系

```
改造前（双轨维护）：
   backend/src/services/*  ──┐
                              ├── 手工同步 ──→ 漂移风险
   dsh-plugin/.../src/core/* ──┘

改造后（SDK 单一权威）：
   @insightforge/core (新建)  ←── 唯一权威实现
        ├── backend (改为消费者)
        ├── dsh-plugin (改为消费者)
        └── mcp-server (新建,基于 SDK)
```

## 二、范围与边界

### 2.1 本期范围（必须完成）

| 编号 | 范围项 | 交付物 |
|------|--------|--------|
| SC-01 | 抽取 `@insightforge/core` 独立 npm 包 | `packages/core/` 目录、GitHub Action 自动发布到 GitHub Packages |
| SC-02 | backend 迁移为 `@insightforge/core` 消费者 | `backend/src/` 内不再保留 `MarketResearcher.ts`、`Aggregator.ts` 等核心算法源码 |
| SC-03 | dsh-plugin 迁移为 `@insightforge/core` 消费者 | `dsh-plugin/.../src/core/` 目录删除，仅保留 Cordis 适配层 |
| SC-04 | 新增 `@insightforge/mcp-server` 包 | `packages/mcp-server/` 目录、暴露 4 个 MCP tools |
| SC-05 | 验证与 Claude Desktop / Cursor / Cline 的端到端对接 | 对接配置文件示例、集成测试用例 |

### 2.2 明确不做（本期范围外）

| 编号 | 暂缓项 | 暂缓理由 |
|------|--------|----------|
| OUT-01 | CLI 工具（`npx insightforge`） | SDK 抽取后是顺手工作，但本期聚焦 MCP，CLI 留待 v1.1 |
| OUT-02 | 前端嵌入组件 `<InsightForgeWidget />` | 需要额外设计组件 API 与样式隔离，工期较长 |
| OUT-03 | REST API 独立 Docker 镜像 | 当前 backend 已提供 REST，独立化不增加价值 |
| OUT-04 | VSCode 扩展 | 依赖 MCP 客户端支持，本期先做 MCP 服务器 |
| OUT-05 | Cloudflare Workers / Edge 部署 | 需要替换 better-sqlite3 为 D1，迁移成本高 |
| OUT-06 | dsh-plugin 增加更多工具 | dsh-plugin 接口保持 v1.0 稳定，工具集合与 MCP 对齐即可 |

> 上述 OUT-* 项并非废弃，而是**明确不在本期需求范围**。SDK 抽取完成后，后续扩展只是增加新包或新工具，不再触碰核心算法。

#### 3.2.2 MCP 协议能力需求

参考 [MCP 规范](https://modelcontextprotocol.io/specification/2025-06-18/server)，服务器需实现以下能力：

| 能力 | 说明 | 是否必须 |
|------|------|----------|
| `tools` | 注册可调用工具（Agent 用） | ✅ 必须 |
| `resources` | 注册可订阅资源（只读数据） | P1（建议） |
| `prompts` | 注册预置 prompt 模板 | P1（建议） |
| `logging` | 通过 MCP 协议向客户端推送日志 | P1（建议） |
| `sampling` | 调用客户端 LLM（极少使用） | ❌ 不实现 |

#### 3.2.3 MCP Tools 需求

暴露 4 个 tools，与 dsh-plugin 工具集合保持一致：

| 工具名 | 描述（出现在 MCP 客户端工具列表） | 输入 Schema | 输出 Schema |
|--------|--------------------------------|-------------|-------------|
| `market_research` | 基于用户提供的产品想法进行市场调研，生成包含市场热度、竞品识别、用户痛点、市场规模估算的结构化报告 | `{ idea: string, depth?: 'quick'\|'standard'\|'deep' }` | `MarketReport`（见 6.1） |
| `search_demand` | 在本地需求库中按关键词检索历史采集的需求数据 | `{ query: string, limit?: number }` | `DemandHit[]` |
| `generate_landing` | 根据产品想法与价值主张生成可分享的验证落地页 HTML | `{ idea: string, value_proposition: string, call_to_action?: string, theme?: 'light'\|'dark', tagline?: string }` | `{ html: string, fileName: string }` |
| `competitor_analysis` | 聚焦指定领域的竞品画像抽取，返回竞品列表及其优劣势 | `{ domain: string, limit?: number }` | `CompetitorEntry[]` |

工具描述文本应包含**触发场景示例**，帮助 Agent 决定何时调用（如 dsh-plugin 的 `market_research` description）。

#### 5.6.1 MCP SDK 选型

#### 5.6.2 传输模式

```typescript
// transport 选择逻辑
const transport = process.env.INSIGHTFORGE_TRANSPORT ?? 'stdio';

if (transport === 'stdio') {
  // 用于本地进程间通信,Claude Desktop / Cline / Cursor 主流方式
  const server = createMcpServer();
  await server.connect(new StdioServerTransport());
} else if (transport === 'http') {
  // 用于远程/多客户端,基于 Express + SSE
  const app = express();
  const transports = new Map<string, SSEServerTransport>();
  app.get('/sse', async (req, res) => {
    const transport = new SSEServerTransport('/messages', res);
    transports.set(transport.sessionId, transport);
    const server = createMcpServer();
    await server.connect(transport);
  });
  app.post('/messages', async (req, res) => {
    const transport = transports.get(req.query.sessionId);
    await transport.handlePostMessage(req, res);
  });
  app.listen(Number(process.env.INSIGHTFORGE_HTTP_PORT ?? 3002));
}
```

#### 5.6.3 工具注册示例（`market_research`）

```typescript
// packages/mcp-server/src/tools/market-research.ts
import { z } from 'zod';
import type { McpServer } from '@modelcontextprotocol/sdk/server/mcp.js';
import type { InsightForgeCore } from '@insightforge/core';

const MarketResearchInput = z.object({
  idea: z.string().min(3).describe('用户的产品想法或项目描述'),
  depth: z.enum(['quick', 'standard', 'deep']).default('standard')
    .describe('调研深度: quick / standard / deep'),
});

export function registerMarketResearchTool(
  server: McpServer,
  core: InsightForgeCore,
): void {
  server.tool(
    'market_research',
    '基于用户提供的产品想法进行市场调研，生成包含市场热度、竞品识别、用户痛点、市场规模估算的结构化报告。',
    MarketResearchInput.shape,
    async (args) => {
      const result = await core.research({
        idea: args.idea,
        depth: args.depth,
      });
      return {
        content: [
          { type: 'text', text: formatReport(result.report) },
          { type: 'resource', resource: { uri: 'insightforge://report/' + result.sessionId, ... } },
        ],
        isError: false,
      };
    },
  );
}
```

#### 5.6.4 配置加载（`config-loader.ts`）

```typescript
import { z } from 'zod';
import { validateConfig, type Config } from '@insightforge/core';

const EnvSchema = z.object({
  INSIGHTFORGE_LLM_PROVIDER: z.string().optional(),
  INSIGHTFORGE_LLM_API_KEY: z.string().min(1, 'LLM_API_KEY 必填'),
  // ... 其他字段
});

export function loadConfig(argv: string[]): { config: Config; transport: 'stdio' | 'http' } {
  const env = EnvSchema.parse(process.env); // 缺失字段直接抛错
  
  const config = validateConfig({
    llmProvider: env.INSIGHTFORGE_LLM_PROVIDER ?? 'deepseek',
    llmApiKey: env.INSIGHTFORGE_LLM_API_KEY,
    // ...
  });
  
  // --config 参数解析（可选）
  const transport = (process.env.INSIGHTFORGE_TRANSPORT ?? 'stdio') as 'stdio' | 'http';
  
  return { config, transport };
}
```

## 十三、常见问题

**Q1：本次需求是否会影响现有用户的部署？**

A：不会。backend API 接口、dsh-plugin 工具接口、SQLite 数据库 schema 均不变。已有用户升级到 v1.1 后,体验完全一致,只是底层由 SDK 统一提供。

**Q2：MCP 服务器与 dsh-plugin 是否冲突？**

A：不冲突。两者可并存安装:
- `dsh-plugin` 运行在 DeepSeek Harness 进程中,供 dsh 生态用户使用
- `mcp-server` 独立运行,供 Claude Desktop / Cursor / Cline 等 MCP 客户端使用

两者共享 `@insightforge/core` 同一份核心代码,但可以配置独立 `dbPath`。

**Q3：是否必须配置 LLM_API_KEY 才能使用 MCP 服务器？**

A：是的,LLM_API_KEY 是必填项。`search_demand` 等只读工具不调用 LLM,但 `market_research` 等核心工具必须 LLM 支持。缺失时进程启动失败。

**Q4：MCP 服务器的 SQLite 数据库可以与 backend 共享吗？**

A：可以,通过设置相同的 `INSIGHTFORGE_DB_PATH`（或 `dbPath`）即可。SQLite WAL 模式支持多进程读写。但建议默认使用独立 dbPath 以避免并发冲突。

**Q5：是否支持远程访问（如部署在服务器上）？**

A：HTTP 模式（`INSIGHTFORGE_TRANSPORT=http`）支持远程访问。建议反向代理前置 HTTPS + Bearer Token 鉴权(本期 NFR-MCP 范围外,留待 v1.2 引入)。

**Q6：本次需求为什么不做 CLI 工具？**

A：本期聚焦 SDK 抽取 + MCP 两个最高价值方向。SDK 抽取完成后,CLI 工具(`npx insightforge`) 只是再增加一个包,工作量约 0.5 天,可作为 v1.1.1 增量发布。

**Q7：MCP 服务器如何计费？**

A：本期不实现计费,所有 LLM / 搜索 API Key 由用户自行配置,InsightForge 不做中转。后续如需团队版统一计费,需新增独立服务（参考 docs/04-用户中心需求文档）。

**Q8：现有 dsh-plugin 是否会废弃？**

A：不会。dsh-plugin 继续作为 DeepSeek Harness 生态的官方集成存在,只是底层实现改为依赖 `@insightforge/core`。

## 附录 B: 术语表

| 术语 | 说明 |
|------|------|
| **MCP** | Model Context Protocol,Anthropic 主导的开放协议,用于 LLM 与外部工具/数据源标准化交互 |
| **MCP Server** | 实现 MCP 协议的服务端,向 MCP 客户端暴露 tools / resources / prompts |
| **MCP Client** | 支持 MCP 协议的 LLM 应用,如 Claude Desktop、Cursor、Cline |
| **stdio transport** | MCP 通过标准输入输出流进行进程间通信的传输方式 |
| **SSE transport** | MCP 通过 Server-Sent Events + HTTP POST 进行网络通信的传输方式 |
| **monorepo** | 单一代码仓库管理多个相关包的工作区模式 |
| **workspace protocol** | pnpm/npm 工作区协议,如 `"workspace:*"` 表示本地包链接 |
| **tools/resources/prompts** | MCP 三大能力,tools 可调用、resources 可订阅、prompts 是预设模板 |
| **WAL mode** | SQLite Write-Ahead Logging 模式,支持多进程并发读写 |
| **Cordis** | DeepSeek Harness 的底层插件框架,主张"一切皆插件" |
| **InsightForgeCore** | SDK 主类,封装关键词提取、聚合、报告生成的完整流程 |
